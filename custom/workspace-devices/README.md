# Устройства пользователей

Самостоятельная административная панель `/workspace-devices` для локального
Rocket.Chat 8.9.0. Показывает активные интерактивные входы пользователей, браузер,
ОС, IP, приблизительный город из офлайн-базы и даты входа/активности. Поддерживает
поиск по логину, страницы результатов и завершение выбранной сессии.

Доступ только роли `admin`. Помимо действующего токена требуется повторно
подтвердить пароль администратора. Если у аккаунта включён второй фактор,
он проверяется штатной реализацией Rocket.Chat. Подтверждение действует 5 минут,
привязано к конкретному токену входа; роль, активность и срок входа проверяются
при каждом запросе. Пять неправильных попыток ограничивают повторную проверку
на минуту. Пароли и коды не сохраняются, хеш пароля проверяет Meteor Accounts.
Именованные API-токены исключены. Текущую сессию администратора завершить из
панели нельзя; используйте обычный выход.

Интерфейс получает только непрозрачный ID устройства, без хешей и токенов входа.
При завершении удаляется именно выбранный токен штатным `Users.unsetOneLoginToken`,
остальные входы пользователя сохраняются. Собственный журнал панели записывает
администратора, целевого пользователя, непрозрачный ID сессии, IP администратора
и время; пароли, токены и переписка в него не попадают. Это журнал действий этой
панели, а не полный аудит всех действий Rocket.Chat.

## API

Все маршруты `/api/v1/workspace-devices/` требуют `X-User-Id` и `X-Auth-Token`.

| Маршрут | Назначение |
| --- | --- |
| `GET status` | Доступ администратора и срок повторного подтверждения |
| `POST reauth` | `passwordDigest` (SHA-256), при необходимости `code` |
| `GET list?offset=0&count=25&user=alice` | Список сессий и полное число совпадений |
| `POST revoke` | `userId`, `deviceId` из собственного списка администратора |
| `GET events?offset=0&count=25` | Журнал завершений сессий |

Неизвестное старое устройство отображается честно: браузер/IP могут отсутствовать
до очередного обращения клиента к API. Статические страницы доступны без входа,
но данные и действия всегда проверяются сервером. В этой версии повторное
подтверждение требует локального пароля; вход через SSO без пароля не поддержан.

## Сборка и установка

```sh
DOCKER_BUILDKIT=0 ./deploy/local/manage.sh build-workspace
docker --context colima-rocketchat image inspect \
  rocketchat-local:8.9.0-workspace-v1 --format '{{.Id}}'
```

Образ включает AI-поиск и «Мои устройства». Его ID указывается в приватном
`deploy/local/.env` (`ROCKETCHAT_IMAGE`), затем `manage.sh start`. При изменении
AI-сервера сначала пересоберите `manage.sh build-ai`. Административная ссылка
«Админ: устройства» находится внизу боковой панели.
