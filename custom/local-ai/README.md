# Локальный AI-поиск

Самостоятельный модуль fork Rocket.Chat 8.9.0: смысловой поиск по переписке,
ответы со ссылками на источники и сводка последних сообщений выбранного канала.
Интерфейс: **http://localhost:3000/local-ai**.

## Как пользоваться

1. Войдите в Rocket.Chat и откройте **AI-поиск** внизу боковой панели.
2. Задайте вопрос своими словами. При необходимости выберите канал или личный чат.
3. Найденные сообщения появятся до завершения генерации ответа. Откройте ссылки,
   чтобы проверить важные детали в исходной переписке.
4. Для сводки выберите один канал и нажмите **Сводка канала**.

Для проверки создан учебный канал `ai-demo-*`. Пример вопроса: «Когда и во сколько
начнётся учебный проект?» В нём содержатся явно обозначенные учебные записи.

Штатный премиальный AI Search и этот раздел — разные возможности интерфейса.
Настройки и проверки лицензии Rocket.Chat не изменялись.

## Модели и ресурсы

- Ollama 0.40.11 работает в Docker без публикации порта на хост.
- EmbeddingGemma 300M используется для смыслового поиска; Qwen3 1.7B — для ответов.
- Названия и полные digest моделей записаны в `models.lock.json`.
- Модели занимают около 2 ГБ; дополнительное место требуется для Docker-образа.
- Ollama ограничена двумя ядрами и 3 ГБ памяти, одновременно загружает одну модель.
  Одновременно выполняется один AI-запрос на экземпляр Rocket.Chat.
- Сообщения и вопросы передаются только локальному Ollama. Внешний LLM API не используется.

На Intel Mac ответы могут формироваться десятки секунд или дольше. Найденные
сообщения доступны отдельно: снимите флажок формирования ответа для поиска без генерации.

## Подготовка и сборка

На установленном локальном стенде:

```sh
./deploy/local/manage.sh prepare-ai
./deploy/local/manage.sh build-ai
docker --context colima-rocketchat image inspect \
  rocketchat-local:8.9.0-ai-v1 --format '{{.Id}}'
```

Подставьте полученный ID в `ROCKETCHAT_IMAGE` в `deploy/local/.env`, затем выполните
`./deploy/local/manage.sh start`. Образ содержит и AI-поиск, и «Мои устройства».
Базовый образ «Мои устройства» собирается автоматически, если его ещё нет.
После изменения исходников повторите сборку и обновите ID.

Файлы моделей сохраняются в томе `rocketchat-local_ollama-models`. Обычная остановка
контейнеров и VM сохраняет их. При обновлении моделей сопоставьте `/api/tags`
с `models.lock.json`, обновите manifest явно и повторите проверки.

## Границы первой версии

- Обрабатываются только доступные текущему пользователю каналы и чаты, в которых
  он участвует. Права проверяются стандартным REST API Rocket.Chat.
- Для поиска берутся последние 100 текстовых сообщений каждого канала, до
  50 каналов и 600 сообщений за запрос. Выбор конкретного канала сужает область.
  Ограничения указаны в интерфейсе; поиск не заменяет полный архивный индекс.
- Сводка строится по шести последним доступным текстовым сообщениям.
- Системные, удалённые и E2E-сообщения исключаются. Содержимое вложений не извлекается.
- Небольшая локальная модель может ошибаться; ответ сопровождается источниками.

## Доступ и данные

Поиск сначала получает подписки и историю через API от имени пользователя.
Запрос ответа принимает только ID сообщений: текст из браузера не используется
в качестве подтверждённого источника. Перед ответом сообщения загружаются заново;
после генерации повторно проверяются доступ и содержимое. При удалении, изменении
источника или отзыве прав ожидающий ответ не выдаётся.

Проверки входа и ограничений REST API сохранены. При HTTP 429 модуль ждёт сброса
лимита, затем повторяет запрос (не более двух повторов). Он не отключает rate limiter.

В MongoDB хранится кэш векторов `rocketchat_local_ai_vectors` с TTL семь дней.
Ключ включает digest модели, ID сообщения и хеш текущего текста. Тексты сообщений
и токены в этот кэш не записываются. При изменении текста вектор пересчитывается.
Глобальный кэш не используется для расширения области доступа пользователя.

При выходе или переключении аккаунта интерфейс скрывает предыдущие результаты.
Вопросы, переписка и ключи авторизации не пишутся в журналы модуля.

## API

Все маршруты требуют стандартные заголовки `X-User-Id` и `X-Auth-Token`:

| Маршрут | Запрос | Результат |
| --- | --- | --- |
| `GET /api/v1/local-ai/status` | Без параметров | Готовность локальных моделей |
| `GET /api/v1/local-ai/rooms` | Без параметров | Собственные подписки пользователя |
| `POST /api/v1/local-ai/search` | `query`, необязательный `roomId` | До шести релевантных источников и охват поиска |
| `POST /api/v1/local-ai/answer` | `query`, `messageIds` (до шести) | Ответ и повторно проверенные источники |
| `POST /api/v1/local-ai/summary` | `roomId` | Краткая сводка и источники |

Вопрос ограничен 500 символами, JSON-запрос — 16 КБ. Выбрать другого пользователя
через параметры API нельзя. Произвольные URL моделей из браузера не принимаются.

## Проверки

```sh
npm test --prefix custom/local-ai
node custom/local-ai/test/live.cjs
node custom/local-ai/test/browser.cjs
./deploy/local/manage.sh check
```

Live-тесты используют отдельные локальные тестовые аккаунты и каналы. Проверяются
права на закрытые каналы, изоляция кэша, реальные embeddings и ответы модели,
ссылки на источники, мобильный интерфейс и очистка результатов при смене аккаунта.
Отчёты и снимки экрана находятся в игнорируемом `deploy/local/.state`.

Модуль и модели локально готовы к последующим доработкам. Источники компонентов:
[Ollama](https://github.com/ollama/ollama),
[Qwen3 1.7B](https://ollama.com/library/qwen3:1.7b),
[EmbeddingGemma](https://ollama.com/library/embeddinggemma).
