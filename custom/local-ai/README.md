# Локальный AI-поиск v2

Смысловой поиск, ответы с источниками и сводки всей доступной истории для fork
Rocket.Chat 8.9.0. Откройте штатную кнопку ✦ рядом с поиском или
http://localhost:3000/local-ai. Текст из строки поиска переносится в форму.
Кнопка запускает наш независимый модуль; платный `chat.rocket.rc-ai` для него
не требуется. Проверки лицензии и другие премиальные возможности не изменяются.

## Использование

1. Войдите в Rocket.Chat, нажмите ✦, задайте вопрос и при необходимости выберите канал.
2. Нажмите «Найти ответ». Можно отключить генерацию и получить только сообщения.
3. Во время фоновой обработки видны этап, число прочитанных сообщений и каналов.
   Кнопка «Отменить обработку» останавливает задачу. После обновления страницы
   вкладка продолжит следить за своей задачей.
4. Все совпадения доступны через «Показать ещё». Ссылки в ответе открывают исходные сообщения.
5. «Сводка канала» обрабатывает всю доступную историю выбранного канала.

Сняты прежние ограничения 50 каналов, 600 сообщений, 100 последних сообщений
канала, 6 источников и 1200 символов сообщения. Нет отдельной квоты на число
AI-запросов. История читается страницами по 100 записей с курсором `(ts, _id)`;
одинаковые временные метки не приводят к пропускам. Поиск обрабатывает все части
длинных сообщений. Сводка и ответ формируются в несколько проходов: все материалы
поступают в обработку, промежуточные сводки объединяются с сохранением ссылок.
При отсутствии проверяемых ссылок генерация повторяется; при повторной неудаче
интерфейс показывает фрагменты материалов с явной пометкой.
Как и любая сводка, итог может опускать детали; небольшая модель может ошибаться.

## Ресурсы и область поиска

Обрабатываются текстовые сообщения из доступных собственных подписок пользователя.
Исключены E2E, системные, скрытые и удалённые сообщения; текст вложений не извлекается.
История включает сообщения с временем не позднее начала выполнения задачи.
Содержимое и права повторно проверяются перед выдачей результата; если источник
изменился, удалён или стал недоступен, запрос нужно повторить.

Это не бесконечные вычислительные ресурсы: Ollama использует 2 CPU и до 3 ГБ RAM,
одновременно выполняется одна задача на экземпляр сервера. Остальные пользователи
попадают в очередь, у каждого допускается одна незавершённая задача.
Количество каналов и сообщений не ограничивается этими размерами порций.
HTTP-запрос ограничен 256 КиБ, ответ выдаётся страницами до 100 сообщений.
Контекст модели 4096 токенов, вывод одного прохода до 512 токенов; большие входы
обрабатываются частями. Отдельный вызов модели имеет тайм-аут 600 секунд.
На Intel Mac большие архивы могут обрабатываться долго.

Ollama 0.40.11, EmbeddingGemma 300M и Qwen3 1.7B работают внутри Docker;
внешний LLM API не используется. Digest моделей записаны в `models.lock.json`.
Веса остаются в томе `rocketchat-local_ollama-models`.

## Доступ и хранение

Модуль проверяет хеш и срок действия стандартного токена входа, активность аккаунта,
подписку, отсутствие блокировки и штатную `canAccessRoomIdAsync` Rocket.Chat
(включая проверки политик доступа). Прямое пакетное чтение использует эти проверки
до чтения и перед выдачей. Ограничения стандартного REST API не изменяются.
Произвольные ID чужих сообщений не дают доступа к их содержимому.

В MongoDB сохраняются векторы с TTL 7 дней, ключ включает digest модели и хеш
полного текста. Метаданные источников и совпадений задач содержат ID, хеши и оценки,
без текста/токенов, TTL 24 часа. Задачи и ответы находятся в памяти процесса,
доступны только владельцу и истекают через час после завершения. Перезапуск
сбрасывает очередь, но сохраняет векторный кэш. Токен активной задачи используется
только в памяти и проверяется при чтении. При выходе или смене аккаунта интерфейс
скрывает результаты. Вопросы и сообщения не пишутся в журналы модуля.

## Сборка

```sh
./deploy/local/manage.sh prepare-ai
DOCKER_BUILDKIT=0 ./deploy/local/manage.sh build-ai
docker --context colima-rocketchat image inspect \
  rocketchat-local:8.9.0-ai-v2 --format '{{.Id}}'
```

Укажите ID образа в `ROCKETCHAT_IMAGE` приватного `deploy/local/.env`, затем
`./deploy/local/manage.sh start`. В образ входит также «Мои устройства».
Нативная кнопка подключается внешним скриптом через Meteor boilerplate API:
событие обрабатывается до React; стандартный поиск продолжает работать.
Если текущий вариант интерфейса не содержит ✦, рядом с поиском добавляется кнопка.
При обновлении Rocket.Chat нужно повторно проверить внутренние импорты и DOM кнопки.
На этом стенде для администратора включён предварительный просмотр `aiSearch`
и серверная настройка `Accounts_AllowFeaturePreview`. В остальных аккаунтах
можно включить AI-панель в персональных настройках предварительного просмотра.

## API

Требуются `X-User-Id` и `X-Auth-Token`. Другой пользователь через параметры не выбирается.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/v1/local-ai/status` | Готовность моделей |
| `GET /api/v1/local-ai/rooms` | Все доступные собственные подписки |
| `POST /api/v1/local-ai/jobs` | `{operation: "search", query, roomId?, generate?}` либо `summary, roomId` либо `answer, query, messageIds` |
| `GET /api/v1/local-ai/jobs/:id` | Состояние и прогресс собственной задачи |
| `POST /api/v1/local-ai/jobs/:id/cancel` | Отмена собственной задачи |
| `GET /api/v1/local-ai/jobs/:id/result?offset=0&count=20` | Проверенные источники, ответ, `nextOffset`, `total` |

Сохранены синхронные `/search`, `/answer`, `/summary` для совместимости. `/search`
возвращает первую страницу и ID задачи для следующих страниц; фоновый API предпочтителен.

## Проверки

```sh
npm test --prefix custom/local-ai
node custom/local-ai/test/live.cjs
AI_TEST_SUMMARY=1 node custom/local-ai/test/jobs-live.cjs
node custom/local-ai/test/browser.cjs
node custom/local-ai/test/native-browser.cjs
./deploy/local/manage.sh check
```

Для тестового порта задайте `AI_TEST_BASE=http://localhost:3001`. Live-проверки
используют отдельные учебные аккаунты и каналы; рабочую переписку не меняют.
