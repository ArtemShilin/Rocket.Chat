# Мои устройства

Самостоятельный модуль fork для просмотра входов текущей учётной записи.
Страница: `/my-devices`, API: `GET /api/v1/account.devices`.

В таблице отображаются устройство, браузер и ОС, IP, приблизительный город,
дата входа и последняя известная активность. Текущий вход помечен отдельно.
Сохранённая авторизация не означает, что устройство сейчас онлайн.

## Сборка и запуск

На подготовленном локальном стенде:

```sh
./custom/account-devices/build.sh
```

Скрипт получает GeoIP-базу, проверяет SHA-256 и собирает образ
`rocketchat-local:8.9.0-devices-v1` поверх закреплённого официального Rocket.Chat.
Зависимости модуля устанавливаются по `package-lock.json` внутри Docker.
В производственный Meteor bundle добавляется серверный модуль загрузки.
Исходники интерфейса и сервера находятся в этом каталоге.

Для переключения добавьте в `deploy/local/.env` строку `ROCKETCHAT_IMAGE=`
со значением из команды:

```sh
docker --context colima-rocketchat image inspect \
  rocketchat-local:8.9.0-devices-v1 --format '{{.Id}}'
./deploy/local/manage.sh start
```

Это фиксирует локальный образ по его неизменяемому ID. На новом компьютере
сначала соберите образ и используйте полученный ID. При следующем изменении
модуля повторите сборку и обновите ID в `.env`.

В боковой панели чата есть ссылка **Мои устройства**; также можно открыть
http://localhost:3000/my-devices напрямую после входа в Rocket.Chat.

## Доступ и сведения об устройствах

- Используется действующий токен стандартного входа Rocket.Chat. API всегда
  определяет владельца на сервере и возвращает только его входы. Параметр
  выбора чужого пользователя не поддерживается.
- Отозванные и просроченные токены исключаются. Администратор также получает
  только собственный список. Управление чужими устройствами не входит в модуль.
- Хеши токенов, сами токены и внутренние документы пользователей не возвращаются.
  Идентификатор строки — дополнительный SHA-256 от хеша токена с отдельным префиксом.
- Используются сведения из мониторинга сессий Rocket.Chat. Дополнительно при
  авторизованных HTTP-запросах фиксируются браузер, ОС, IP и время наблюдения.
  Запись обновляется не чаще раза в минуту на вход; при открытии списка — сразу.
- Для старых входов без сохранённых метаданных отображается «Нет данных».
  Модель компьютера или ОС может быть скрыта самим браузером.
- Дополнительные наблюдения хранятся в MongoDB в коллекции
  `rocketchat_account_device_observations`; TTL ограничен временем жизни токена.
  Коллекция включается в обычную резервную копию базы Rocket.Chat.
- Интерфейс использует текущий вход из localStorage того же origin. После
  выхода из аккаунта или смены аккаунта данные предыдущего входа скрываются.
- IP берётся из сетевого соединения. В этой конфигурации обратного HTTP-прокси
  нет, поэтому `X-Forwarded-For` и `X-Real-IP` не используются как источник IP.

## Город

Определение города выполняется локально по **DB-IP City Lite**. IP пользователей
не отправляются сервисам геолокации. Источник, версия, лицензия и контрольные
суммы базы указаны в `geoip-manifest.json`. Файл MMDB исключён из Git.
Для обновления базы нужно явно изменить manifest и повторно проверить результат.

Для внутренних, loopback и служебных адресов отображается «Локальная сеть»;
для неизвестных адресов — «Не определён». VPN, мобильная сеть и NAT влияют на
определение города. На локальном Docker-стенде адресом может быть внутренний
шлюз Docker, а не публичный адрес компьютера.

Данные: [DB-IP](https://db-ip.com/db/download/ip-to-city-lite),
лицензия [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Атрибуция также показана в интерфейсе.

## Проверка

```sh
npm ci --prefix custom/account-devices --ignore-scripts --no-audit --no-fund
npm test --prefix custom/account-devices
node custom/account-devices/test/live.cjs
./deploy/local/manage.sh check
```

Live-проверка использует существующий локальный тестовый fixture, Chrome и
`playwright-core` из `deploy/local/.state/browser`. Проверяются два устройства
одного аккаунта, изоляция другого аккаунта, отказ неавторизованным запросам,
валидация пагинации и исключение устройства после обычного выхода.
Результаты и снимки экрана сохраняются в игнорируемый `.state`.

Модуль привязан к формату Meteor bundle и механизмам авторизации Rocket.Chat
8.9.0. При обновлении основной версии повторно проверьте сборку и live-тесты.
