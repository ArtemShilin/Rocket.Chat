# Локальный Rocket.Chat

Стенд для проверки Rocket.Chat и последующей разработки в fork
[ArtemShilin/Rocket.Chat](https://github.com/ArtemShilin/Rocket.Chat/tree/custom/main).
Рабочая ветка `custom/main` основана на официальном теге `8.9.0`.

В локальной установке добавлен раздел **Мои устройства**: ссылка внизу боковой
панели или http://localhost:3000/my-devices. Отображаются устройство, IP и
приблизительный город входов текущей учётной записи.
[Код, сборка и проверки модуля](../../custom/account-devices/README.md).

Добавлен **AI-поиск**: http://localhost:3000/local-ai. Локальные модели ищут по
смыслу в доступной переписке, формируют ответы со ссылками и сводки последних
сообщений канала. [Подготовка моделей, сборка и границы поиска](../../custom/local-ai/README.md).

## Быстрый запуск

На подготовленном Mac выполните:

```sh
cd /Users/zzz/Projects/Rocket.Chat
./deploy/local/manage.sh start
```

Откройте **http://localhost:3000**. Первый запуск создаёт администратора `admin`
со случайным паролем. Посмотреть локальные реквизиты:

```sh
./deploy/local/manage.sh credentials
```

Пароль находится в `deploy/local/.env` с правами `600`. Файл исключён из Git.
При смене пароля через интерфейс обновите `ADMIN_PASS` в `.env` для проверок.
Переменные `ADMIN_*` создают первого администратора, но не сбрасывают пароль
у существующего. Не удаляйте `.env` при существующем томе базы.

## Управление

Все команды выполняются из корня репозитория:

| Команда | Действие |
| --- | --- |
| `./deploy/local/manage.sh start` | Запустить VM при необходимости и дождаться готовности контейнеров |
| `./deploy/local/manage.sh stop` | Остановить контейнеры, сохранив данные |
| `./deploy/local/manage.sh stop-vm` | Остановить контейнеры и VM |
| `./deploy/local/manage.sh status` | Статус контейнеров |
| `./deploy/local/manage.sh logs rocketchat` | Последние журналы приложения |
| `./deploy/local/manage.sh check` | Проверка версии, входа, переписки и вложения через API |
| `./deploy/local/manage.sh browser-check` | Проверка входа и доставки сообщений в двух браузерных сеансах |
| `./deploy/local/manage.sh backup` | Сохранить архив базы в `deploy/local/backups` |
| `./deploy/local/manage.sh compose ...` | Дополнительная команда Compose с правильным контекстом и настройками |

После перезагрузки macOS запускайте стенд командой `start`. Автозапуск не настроен.

## Устройство стенда

- Colima: профиль `rocketchat`, VZ, x86_64, 3 vCPU, 6 ГБ RAM, диск данных до 30 ГБ.
- Docker: контекст `colima-rocketchat`. Скрипт всегда указывает его явно.
- Rocket.Chat: базовый официальный образ 8.9.0 с модулями «Мои устройства» и AI-поиска;
  MongoDB: 8.0; NATS: 2.11. Базовые образы зафиксированы digest в `images.env`.
  Локальный образ приложения закреплён ID через `ROCKETCHAT_IMAGE` в `.env`.
- Единственный опубликованный порт: `127.0.0.1:3000`. MongoDB и NATS доступны
  только внутри сети Compose.
- MongoDB работает как одиночный replica set `rs0`. Инициализация повторно
  использует существующий replica set.
- Пользователи, сообщения и вложения GridFS хранятся в томе
  `rocketchat-local_mongodb` внутри VM. Пересоздание контейнеров сохраняет их.
- Самостоятельная регистрация пользователей выключена: их создаёт администратор.
- Для локальной проверки SMTP и регистрация workspace в Rocket.Chat Cloud не
  настроены. Email-коды 2FA отключены; TOTP остаётся доступным.
- Ограничение журналов: три файла по 10 МБ на контейнер.
- Ollama работает во внутренней сети Docker; модели сохраняются в томе
  `rocketchat-local_ollama-models`. Для восстановления их можно скачать повторно
  командой `./deploy/local/manage.sh prepare-ai`; архив базы их не включает.

Удаление тома, `docker compose down -v` или удаление VM уничтожит данные стенда.

## Инструменты на этом Mac

Стенд установлен на Intel Mac mini с macOS 13.7.8 и 16 ГБ RAM. Поддержка
виртуализации проверена; гостевая Linux использует ядро 6.8.

В `~/.local/bin` установлены Colima 0.10.3, Lima 2.2.1, Docker CLI 29.9.2
и GitHub CLI 2.103.2. Compose 5.6.1 установлен в `~/.docker/cli-plugins`.
Точные контрольные суммы установочных файлов записаны в `runtime-versions.json`.
Системный Homebrew не использовался.

На другом Mac сначала установите эти инструменты из официальных сборок для
своей архитектуры. Конфигурация этого стенда рассчитана на Intel Mac с macOS 13.5+.

Проверка в браузере использует установленные Node.js, npm и Google Chrome.
`browser-check` устанавливает только `playwright-core@1.64.1` в игнорируемый
каталог `.state/browser`. Chrome запускается без интерфейса с отдельным временным
профилем; пользовательский профиль Chrome не используется.

## Повторная проверка

```sh
./deploy/local/manage.sh check
./deploy/local/manage.sh browser-check
```

При первом вызове `check` создаются два тестовых пользователя с уникальными
именами, канал, личный чат и текстовое вложение. Последующие проверки читают
эти же данные, что позволяет проверить сохранность после перезапуска.
`browser-check` дополнительно отправляет новые сообщения в обоих направлениях
через две независимые браузерные сессии без обновления страницы получателя.

Имена и пароли тестовых пользователей, отчёты и снимки экрана находятся в
`deploy/local/.state` и исключены из Git. Каталог имеет права `700`.
Не удаляйте тестовые данные, пока используете сохранённый `fixture.json`.
Для создания нового набора удалите только `deploy/local/.state/fixture.json`
и повторите `check`.

## Резервная копия и восстановление

Чтобы сообщения и вложения не менялись во время резервирования, остановите
только приложение, оставив MongoDB работающей:

```sh
./deploy/local/manage.sh compose stop rocketchat
./deploy/local/manage.sh backup
./deploy/local/manage.sh start
```

Архив включает коллекции Rocket.Chat и содержимое вложений GridFS. Храните
копию вне VM и вне этого компьютера, если данные важны. Архивы содержат
пользовательские данные и реквизиты входа; они исключены из Git и создаются
с правами `600`. Резервирование не заменяет проверку восстановления.

Восстановление **заменяет текущие коллекции** данными архива. Сначала сохраните
резервную копию текущей базы, затем выполните с нужным путём к архиву:

```sh
./deploy/local/manage.sh compose stop rocketchat
./deploy/local/manage.sh compose exec -T mongodb \
  mongorestore --archive --gzip --drop --nsInclude 'rocketchat.*' \
  < deploy/local/backups/ИМЯ_АРХИВА.archive.gz
./deploy/local/manage.sh start
./deploy/local/manage.sh check
```

Если архив содержит других пользователей/пароли, обновите `.env` и тестовый
fixture перед проверкой.

## Дальнейшая разработка

`origin` указывает на ваш fork, `upstream` — на `RocketChat/Rocket.Chat`.
Развивайте изменения в отдельных ветках от `custom/main`, затем объединяйте
их через pull request в эту ветку. Основные файлы приложения сейчас не изменены.

Стенд запускает **собственный образ поверх официального** с модулями из
`custom/account-devices` и `custom/local-ai`. Для изменения модулей повторите сборку AI-образа и обновите
`ROCKETCHAT_IMAGE` в `.env` на новый ID по инструкции модуля. Изменения исходников
в fork автоматически в контейнер не попадают. Для изменения основного React/Meteor
приложения потребуется полная сборка его исходников.

Перед обновлением Rocket.Chat создавайте резервную копию, проверяйте требования
к MongoDB и обновляйте образы явно в `images.env`. При переходе на новую версию
обновите также ожидаемую версию в `check.py`. Затем запускайте `start`,
`check` и `browser-check`. Обратная установка старого образа не отменяет миграции
базы: для возврата может потребоваться совместимая резервная копия.

## Административное управление устройствами

Откройте **Админ: устройства** внизу боковой панели или
http://localhost:3000/workspace-devices. Требуется роль администратора и повторное
подтверждение пароля. Панель показывает все активные интерактивные входы,
позволяет найти пользователя и завершить конкретный вход с записью в журнал.
Остальные входы пользователя сохраняются.

Сборка: `DOCKER_BUILDKIT=0 ./deploy/local/manage.sh build-workspace`.
Подробности: [модуль устройств](../../custom/workspace-devices/README.md),
[обзор следующих возможностей](../../custom/PREMIUM_REVIEW.md).
